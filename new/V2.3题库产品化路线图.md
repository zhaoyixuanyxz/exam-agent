# 试卷考点拆解助手 V2.3 路线图：题库产品化

## 1. 文档说明

- 对应前置版本：
  - `new/迭代版需求文档_v2.md`
  - `new/V2开发路线图_任务清单.md`
  - `new/V2任务表.md`
  - `docs/V2_2_audit_and_acceptance.md`
- 文档目标：定义 `V2.3` 如何从 `V2.2 预研原型` 进入“题库产品化”阶段。
- 文档定位：产品与研发的下一阶段路线图，不替代详细 PRD。

---

## 2. 当前起点判断

`V2.2` 已经完成两件关键事情：

1. 把确认后的结构化题目沉淀为 `question_assets`
2. 提供多卷聚合分析 API 和前端原型页

但当前仍属于“题库化预埋”而非“完整题库产品”：

- 题目还不能被方便地检索、筛选、复用
- 考点还不是统一主数据
- 多卷分析还是基础统计原型
- 缺少审核、治理、权限与组织化能力

因此，`V2.3` 的核心目标不是继续加聊天能力，而是完成：

1. **题库主数据成型**
2. **题库工作台可用**
3. **教研分析看板成型**
4. **组织化治理能力起步**

---

## 3. V2.3 阶段目标

### 3.1 总目标

让产品从“能沉淀题目资产”升级为“能稳定管理、检索、复用、分析题目资产”的题库产品雏形。

### 3.2 完成定义

满足以下条件可视为 `V2.3` 完成：

1. 题目具备稳定标识与更完整的元数据结构。
2. 用户能在前台检索、筛选、预览题目资产。
3. 用户能基于题库结果进行复用或组卷起步操作。
4. 多卷分析从原型升级为较完整的教研分析页。
5. 系统具备基础的审核、纠错或治理入口。

---

## 4. 核心模块

## 4.1 模块一：题库主数据升级（P0）

### 目标

把 `question_assets` 从“结构化行数据”升级为“可长期运营的题库资产”。

### 功能方向

- 为题目增加更完整字段：
  - 题目唯一业务标识
  - 来源试卷信息
  - 年级 / 学科
  - 题型
  - 题干 / 选项
  - 标准答案
  - 解析
  - 难度
  - 教材版本 / 章节
  - 考点标准标签
  - 质量状态（待确认 / 已审核 / 已废弃）
- 建立题目标识策略：
  - 先支持“结构化版本内唯一”
  - 再补“跨版本稳定指纹”
- 为未来去重与合并预留字段。

### 价值

- 解决“题目能存但不好管”的问题。
- 为检索、筛选、分析、组卷打基础。

---

## 4.2 模块二：考点主数据与标签体系（P0）

### 目标

解决当前 `knowledge_point_key` 只能按字面聚合、不能稳定跨卷复用的问题。

### 功能方向

- 建立考点主表：
  - 标准 key
  - 标准名称
  - 别名 / 同义项
  - 章节归属
  - 学科 / 年级适用范围
- 建立题目与考点的标准关联关系。
- 提供人工归并入口：
  - 同义考点合并
  - 错误考点修正
  - 未识别考点补标
- 为教材版本与章节树建立映射。

### 价值

- 让多卷分析从“按 key 拼接”走向“按真实考点分析”。
- 为题库检索和教研分析建立统一语言。

---

## 4.3 模块三：题库检索与浏览工作台（P0）

### 目标

让教师或教研人员可以真正使用已沉淀的题目资产。

### 功能方向

- 新增题库列表页 / 工作台：
  - 关键词检索
  - 按年级、学科、题型、考点、章节、来源筛选
  - 按时间、质量状态、难度排序
- 新增题目详情页：
  - 题干、选项、答案、解析、考点、来源
  - 关联原始材料与结构化版本
- 新增批量选择与收藏 / 加入组卷篮能力。

### 价值

- 从“资产沉淀”进入“资产可用”阶段。
- 让题库真正服务备课、选题和复用。

---

## 4.4 模块四：题库复用与组卷起步（P1）

### 目标

让题库不仅能看，还能用于实际教学产出。

### 功能方向

- 支持从题库中选择题目，加入临时题单。
- 支持基础组卷配置：
  - 题量
  - 题型配比
  - 考点范围
  - 难度区间
- 支持导出初版练习卷 / 教师参考版。
- 保留与当前练习生成链路的兼容关系。

### 价值

- 让题库真正进入“教学交付”闭环。
- 打通“分析 -> 选题 -> 组卷 -> 导出”的链路。

---

## 4.5 模块五：教研分析看板升级（P1）

### 目标

把 V2.2 的多卷分析原型升级为更接近教研场景的分析产品。

### 功能方向

- 分析页升级：
  - 考点覆盖对比
  - 高频题型趋势
  - 重复考点热度
  - 章节分布
  - 试卷差异摘要
- 增加图表化表达与可视化摘要。
- 支持按条件选择分析范围：
  - 指定时间范围
  - 指定年级 / 学科
  - 指定来源集合
- 支持导出分析结果或生成简版教研报告。

### 价值

- 从“工程可验证原型”升级为“教研可用页面”。
- 提升产品在备课、命题复盘、教研会议中的使用价值。

---

## 4.6 模块六：审核与治理能力（P1）

### 目标

避免题库随着沉淀规模增长而失控。

### 功能方向

- 题目审核状态流：
  - 待审核
  - 已审核
  - 已修正
  - 已废弃
- 异常处理入口：
  - 重复题
  - 缺答案
  - 缺解析
  - 考点冲突
- 人工纠错入口：
  - 改题型
  - 改考点
  - 改难度
  - 改章节标签

### 价值

- 保证题库质量。
- 为后续组织化协作和规模增长做准备。

---

## 4.7 模块七：组织与权限基础（P2）

### 目标

让题库从“个人工具”走向“团队资产”。

### 功能方向

- 引入基础角色：
  - 管理员
  - 教研员
  - 普通教师
- 区分数据范围：
  - 我的题目
  - 本团队题目
  - 公共题目
- 记录关键操作日志：
  - 创建
  - 编辑
  - 审核
  - 删除

### 价值

- 为学校/机构级使用做好准备。
- 让题库资产可管理、可协作、可追责。

---

## 5. 建议排期

### 阶段 A：主数据与检索底座

- 题目模型升级
- 考点主数据表
- 题目检索接口
- 基础题库列表页

### 阶段 B：题库可用化

- 题目详情页
- 收藏 / 题单 / 组卷篮
- 题库筛选与排序增强
- 基础导出链路

### 阶段 C：教研分析升级

- 多卷分析看板化
- 图表与报告导出
- 统计口径标准化

### 阶段 D：治理与组织化

- 审核流
- 异常修正
- 权限与数据范围
- 审计日志

---

## 6. 建议任务拆解原则

1. 先做主数据，再做页面，不要先做题库 UI 再补模型。
2. 先做可检索、可筛选，再做复杂组卷。
3. 教研分析必须建立在考点主数据标准化之后，否则结果可信度不足。
4. 治理能力不要拖到最后完全缺失，至少应与题库工作台同期启动最小闭环。

---

## 7. 主要风险

- 题目标识不稳定，会导致后续去重、复用、审核成本非常高。
- 考点标准化如果缺位，多卷分析会持续停留在“原型统计”层。
- 若先堆前台功能而忽略审核与治理，题库质量会快速下降。
- 若不尽早设计权限与数据范围，后续组织化改造成本会很高。

---

## 8. 建议的优先级判断

如果资源有限，建议严格按以下顺序推进：

1. `题库主数据升级`
2. `考点主数据与标签体系`
3. `题库检索与浏览工作台`
4. `教研分析看板升级`
5. `题库复用与组卷起步`
6. `审核与治理能力`
7. `组织与权限基础`

---

## 9. 结论

`V2.0` 到 `V2.2` 解决的是“让试卷分析助手更像产品”。  
`V2.3` 应该解决的是“让产品真正长成题库系统与教研分析系统”。

因此，`V2.3` 的核心判断标准不应再是：

- Agent 是否更聪明
- 页面是否多了一个入口

而应转为：

1. 题目是否能稳定沉淀为长期资产
2. 教师是否能方便检索、复用这些资产
3. 教研人员是否能基于这些资产得到可信分析
4. 系统是否具备持续增长后的治理能力

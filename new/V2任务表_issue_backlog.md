# 试卷考点拆解助手 V2 任务表 / Issue Backlog

## 1. 文档说明

- 对应文档：
  - `new/迭代版需求文档_v2.md`
  - `new/V2开发路线图_任务清单.md`
- 文档用途：将路线图进一步拆为可排期、可分配、可验收的任务表
- 使用方式：
  - 可直接拆分为 GitHub Issues / 看板卡片
  - 可直接按周或 Sprint 做排期
  - 可作为研发、测试、产品对齐的执行清单

---

## 2. 使用规则

### 2.1 状态定义

- `todo`：尚未开始
- `ready`：前置依赖已满足，可进入开发
- `doing`：开发中
- `review`：已提测或待产品验收
- `done`：完成并通过验收
- `blocked`：存在依赖阻塞

### 2.2 优先级定义

- `P0`：首发阻塞项
- `P1`：版本增强项
- `P2`：预研或后续迭代项

### 2.3 负责人类型

- `FE`：前端
- `BE`：后端
- `FULLSTACK`：全栈
- `QA`：测试
- `PM`：产品

---

## 3. 推荐排期视图

### 3.1 建议节奏

如果按 2 周一个 Sprint，可采用以下节奏：

- Sprint 1：V2.0 数据与接口基础
- Sprint 2：V2.0 前端主流程与结构化确认
- Sprint 3：V2.0 多材料管理 + 联调验收
- Sprint 4：V2.1 练习生成配置 + 产物中心
- Sprint 5：V2.1 历史增强 + 验收
- Sprint 6+：V2.2 资产沉淀与多卷分析预研

### 3.2 交付策略

优先交付可上线最小包：

1. `V2.0 必做包`
2. `V2.1 增强包`
3. `V2.2 预研包`

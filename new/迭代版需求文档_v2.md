# 试卷考点拆解助手迭代版需求文档（V2）

## 1. 文档说明

- 产品名称：试卷考点拆解助手（`exam-agent`）
- 文档类型：混合版 PRD（强执行型）
- 文档用途：用于明确下一阶段产品迭代目标、功能范围、优先级、验收标准与版本节奏
- 目标读者：产品、研发、设计、测试
- 文档状态：V2 迭代版草案

---

## 2. 产品背景

当前产品已具备从试卷材料输入到产物生成的基本主链路能力，支持教师上传 PDF / Word、粘贴 URL 或文本，通过 Agent 完成试卷结构化、考点分析、分块练习 PDF 生成，并支持多轮对话、多会话历史、多材料管理与产物下载。

从产品演进阶段来看，当前版本已完成“可用性验证”，证明产品具备真实工作流价值；但距离“高频稳定使用”的教学工具仍有明显差距。主要问题不在于功能数量不足，而在于：

1. 结果虽能生成，但用户对解析与结构化结果缺少确认和修正能力，信任感不足。
2. 高频操作仍主要依赖聊天表达，教师使用成本偏高，稳定性不足。
3. 输出产物虽然可下载，但距离“直接用于教学交付”还有一段距离。
4. 已有多材料和会话能力，但尚未沉淀成更长期的题目资产与教学资产。

因此，V2 版本的核心目标不是单纯增加更多 Agent 能力，而是把产品从“能做事的聊天工具”升级为“可信、稳定、可交付的教师工作台”。

## 3. 版本定位

### 3.1 一句话定位

面向教师的试卷结构化与教学材料生成助手。

### 3.2 V2 版本定位

在保留现有对话式灵活性的基础上，引入结构化确认、显式操作流与可交付产物能力，降低教师使用门槛，提升结果可信度和复用价值。

### 3.3 本版本关键词

- 结果可信
- 操作稳定
- 输出可交付
- 数据可沉淀

---

## 4. 用户角色与核心场景

### 4.1 目标用户

1. 一线任课老师  
日常需要分析试卷、整理考点、生成练习、备课或布置作业。

2. 教研组老师 / 备课组长  
需要对多份试卷做横向比较、提炼高频考点、统一输出练习材料。

3. 教培机构教研人员  
关注题目沉淀、题型拆分、难度分层和批量生成材料效率。

### 4.2 核心使用场景

1. 老师拿到一套新试卷，想快速拆出考点并生成配套练习。
2. 老师上传一份 PDF 后，希望按页拆分材料并分别进行分析。
3. 老师希望从一套试卷中提炼某些考点，批量生成可打印练习。
4. 老师在多份材料之间切换，希望历史可追溯、结果不串台。
5. 老师在解析后希望修正识别错误，再继续生成教学材料。

## 5. 现状能力拆解

本节用于拆解旧版需求文档中的既有能力，并作为 V2 设计基础。

### 5.1 已具备能力

#### 5.1.1 输入与解析

- 支持 PDF、Word（docx）、URL、粘贴文本四类输入源
- 上传文件大小受后端配置限制
- 解析失败返回可读错误信息

#### 5.1.2 对话与 Agent

- 支持 SSE 流式回复
- 每轮对话绑定 `conversation_id` 与当前 `paper_id`
- 基于 LangGraph 的多轮状态延续
- 支持工具链处理：结构化、考点分析、出题等

#### 5.1.3 产物与展示

- 支持生成 Markdown 与练习 PDF
- 产物可通过 `/export-files/...` 下载
- 前端已对部分模型输出做展示层清洗，例如隐藏大块练习 JSON

#### 5.1.4 会话管理

- 支持会话列表、历史回放、新建、删除
- 支持误关页面后的会话恢复
- 支持地址栏与当前会话同步

#### 5.1.5 多会话并行

- 会话 UI 已按 `conversation_id` 隔离
- 流式任务按会话分桶管理
- 支持后台继续生成
- 支持新标签页并行操作

#### 5.1.6 多材料处理

- 支持同会话下多份材料
- 支持 PDF 按页拆分
- 支持按 `paper_id` 区分不同材料的分析与产物
- 支持多考点批量生成练习 PDF

### 5.2 当前版本主要问题

#### 5.2.1 可信性问题

- 结构化结果直接进入后续流程，缺少用户确认环节
- OCR / 解析错误一旦进入后续流程，会放大到考点分析和出题环节
- 用户很难知道当前系统到底识别了什么、依据什么生成结果

#### 5.2.2 可用性问题

- 高频操作过度依赖聊天输入，缺少显式按钮和流程入口
- 多材料依赖 `paper_id` 心智，对教师不够友好
- 历史会话虽然可恢复，但材料命名和状态感知仍偏弱

#### 5.2.3 交付性问题

- 输出结果偏向“生成完成”，而不是“可直接用于教学”
- 缺少分层练习、答案分离、解析分离、A/B 卷等常见教学交付形式

#### 5.2.4 资产化问题

- 当前以对话驱动为主，结构化结果和题目尚未沉淀为长期可检索资产
- 多份试卷之间暂未形成横向分析能力

## 6. V2 版本目标

### 6.1 业务目标

1. 提升教师对解析和生成结果的信任度，减少“黑盒感”。
2. 提升核心高频流程的完成率与可重复使用率。
3. 让产出结果更接近老师可直接打印、发学生、备课使用的成品。
4. 为后续题库化与多试卷对比分析建立结构化基础。

### 6.2 产品目标

1. 建立“解析 -> 确认 -> 分析 -> 生成”的稳定工作流。
2. 将高频操作从聊天表达升级为显式功能入口。
3. 将多材料从技术心智改为教师可理解的材料管理方式。
4. 建立产物规格体系，使结果具备标准化输出能力。

### 6.3 成功指标（建议）

- 结构化结果确认率 >= 70%
- 上传后成功完成一次完整工作流的用户占比提升
- 练习 PDF 二次下载 / 使用率提升
- 用户在单次会话中的重复修改与重试次数下降
- 多材料场景下的目标材料选错率显著下降

---

## 7. 本轮迭代策略

### 7.1 设计原则

1. 先提升高频核心链路质量，再扩展低频高级功能。
2. 优先做可见、可理解、可控制的产品能力，而非继续堆叠隐藏在聊天里的能力。
3. 优先建设结构化结果的可信闭环，为后续资产沉淀铺路。

### 7.2 版本范围边界

#### 本轮纳入

- 结构化结果确认与修正
- 显式任务入口与状态流
- 更适合教学交付的生成配置
- 多材料的友好化管理
- 历史会话与产物管理增强

#### 本轮暂不纳入

- 学生个体画像与个性化推题
- 班级成绩数据接入
- 完整题库检索后台
- 多校多角色权限系统
- 商业化、计费、团队协作体系

## 8. 功能需求总览

### 8.1 优先级定义

- P0：必须上线。直接影响核心链路可用性与用户信任。
- P1：重要增强。提升效率、复用与交付质量。
- P2：探索能力。为后续版本做铺垫。

### 8.2 功能清单

| 模块 | 功能 | 优先级 |
|---|---|---|
| 解析结果确认 | 结构化结果预览、修正、确认 | P0 |

| 多材料管理 | 材料命名、选择、切换优化 | P0 |

## 9. 详细功能需求

## 9.1 模块一：结构化结果确认中心（P0）

### 9.1.1 目标

在试卷解析完成后，为用户提供一个可见、可改、可确认的结构化结果层，作为后续考点分析和练习生成的基础。

### 9.1.2 功能说明

1. 系统完成试卷结构化后，不直接静默进入后续流程，而是展示“结构化结果卡片”。
2. 结果卡片至少包含以下信息：
   - 年级
   - 学科
   - 试卷标题
   - 题目总数
   - 题号列表
   - 题型识别结果
   - 页码或来源范围
3. 用户可对关键字段进行轻量修正。
4. 用户点击“确认结构化结果”后，后续分析和生成默认基于确认后的版本。
5. 若用户未确认，系统不得将其标记为“已完成结构化”。

### 9.1.3 交互要求

- 展示需尽量卡片化、清单化，避免大段原文堆叠。
- 对明显异常结果给出提醒，例如题号重复、题号跳号、题目为空。
- 支持“重新结构化”操作。

### 9.1.4 验收标准

1. 用户能在界面上直接看到结构化结果摘要。
2. 用户能修正至少一类关键字段并保存。
3. 后续考点分析与练习生成使用确认后的结构化版本。
4. 当结构化异常时，界面有明确提示而不是直接进入下一步。

---

## 9.2 模块二：显式工作流与状态引导（P0）

### 9.2.1 目标

将高频动作从纯聊天表达升级为显式产品化流程，降低教师使用门槛。

### 9.2.2 功能说明

在主界面提供清晰的流程入口和步骤状态，至少包含：

1. 上传材料
2. 结构化试卷
3. 分析考点
4. 生成练习
5. 下载产物

### 9.2.3 状态要求

每个步骤至少支持以下状态：

- 未开始
- 进行中
- 待确认
- 已完成
- 失败

### 9.2.4 产品要求

1. 保留聊天输入能力，但不应再要求用户必须通过自然语言才能触发高频操作。
2. 用户在任何关键节点都应知道“当前系统进行到哪一步”。
3. 当步骤失败时，需提供明确重试入口。

### 9.2.5 验收标准

1. 新用户不输入复杂指令，也能完成一次完整主流程。
2. 页面上可明确看到当前阶段和下一步建议动作。
3. 错误与重试入口明确，不依赖用户重新组织自然语言。

---

## 9.3 模块三：多材料友好化管理（P0）

### 9.3.1 目标

将当前以 `paper_id` 为核心的技术识别方式，升级为教师易理解的材料管理方式。

### 9.3.2 功能说明

1. 每份材料在会话内显示友好名称，命名建议采用：
   - 原文件名
   - 上传时间
   - 自动识别标题
2. 支持对材料重命名。
3. 在执行考点分析、练习生成、按页拆分等操作前，界面明确显示当前目标材料。
4. 当会话内存在多份材料时，优先使用材料选择器，而不是要求用户记忆 `paper_id`。

### 9.3.3 验收标准

1. 多材料场景中，用户能通过名称而不是 ID 选择材料。
2. 所有关键动作前都能看到当前绑定材料。
3. 用户能完成重命名并在历史中持续看到名称。

---

## 9.4 模块四：练习生成配置升级（P1）

### 9.4.1 目标

让练习生成结果更接近老师真实教学交付需要，而非单一的默认 PDF 输出。

### 9.4.2 功能说明

练习生成前提供配置项，建议包括：

1. 题量
2. 目标考点
3. 题型范围（选择题、填空题、综合题等）
4. 难度层级（基础 / 提升 / 冲刺）
5. 输出形式：
   - 仅题目
   - 题目 + 答案
   - 题目 + 答案 + 解析
6. 试卷模式：
   - 单份练习
   - A/B 卷

### 9.4.3 验收标准

1. 用户能在生成前看到并设置核心配置项。
2. 最终导出内容与配置一致。
3. 至少支持“仅题目”和“题目+答案”两种输出模式。

---

## 9.5 模块五：产物中心（P1）

### 9.5.1 目标

把当前“生成文件列表”升级为更可管理的产物中心。

### 9.5.2 功能说明

1. 对产物按类型分类展示：
   - 考点说明
   - 练习 PDF
   - 答案 / 解析
   - 结构化结果
2. 展示生成时间、所属材料、所属考点或任务来源。
3. 支持从某一产物直接继续操作，例如：
   - 从考点说明继续生成练习
   - 从某份练习重新生成

### 9.5.3 验收标准

1. 用户能清楚区分不同产物类型。
2. 用户能追溯产物来源材料。
3. 用户能从产物触发后续动作，而不必重新描述需求。

---

## 9.6 模块六：会话与历史体验增强（P1）

### 9.6.1 目标

提升历史回访、继续操作与重试效率。

### 9.6.2 功能说明

1. 会话列表支持更多预览信息：
   - 学科
   - 年级
   - 材料数量
   - 最近产物类型
2. 支持快捷动作：
   - 继续上次流程
   - 重新生成最近结果
   - 查看该会话的所有材料
3. 支持按学科 / 日期筛选历史会话。

### 9.6.3 验收标准

1. 用户能快速识别某会话主要内容。
2. 用户能在历史会话中快速续作，不需要从头问起。

---

## 9.7 模块七：结构化资产沉淀（P2）

### 9.7.1 目标

将当前一次性对话结果逐步沉淀为可复用的题目与考点资产。

### 9.7.2 功能说明

1. 将结构化后的题目保留为可追溯记录。
2. 每道题关联至少以下元信息：
   - 来源试卷
   - 题号
   - 题型
   - 考点
   - 结构化版本
3. 为后续题库化、检索、复用打基础。

### 9.7.3 说明

本模块在 V2 版本中以“数据结构与落盘能力预埋”为主，不强求完整前台题库产品形态。

---

## 9.8 模块八：多试卷横向分析（P2）

### 9.8.1 目标

从“单卷处理”向“多卷分析”演进，增强产品的教研价值。

### 9.8.2 功能说明

1. 支持选择两份及以上材料进行横向分析。
2. 支持输出以下维度的对比结果：
   - 考点覆盖差异
   - 高频题型差异
   - 重复考点统计
   - 重点章节分布

### 9.8.3 说明

本模块建议作为 V2 预研能力，不作为首发上线阻塞项。

## 10. 核心流程设计

### 10.1 主流程

1. 上传或导入材料
2. 系统解析材料
3. 生成结构化结果
4. 用户确认 / 修正结构化结果
5. 系统执行考点分析
6. 用户选择目标考点与生成配置
7. 系统生成教学产物
8. 用户下载或继续衍生操作

### 10.2 多材料流程

1. 用户在同一会话中上传多份材料
2. 系统为每份材料生成友好名称
3. 用户通过材料选择器选定目标材料
4. 所有分析与生成动作均绑定所选材料

### 10.3 异常流程

1. 解析失败：提示失败原因与重新上传 / 重试入口
2. 结构化异常：提示异常项并要求确认或修正
3. 生成失败：保留当前上下文并提供重试入口

---

## 11. 非功能需求

### 11.1 性能与稳定性

- SSE 长任务需具备稳定展示与断连恢复策略
- 多会话并行时不得串台
- 同会话重复提交时需避免重复任务污染状态

### 11.2 可理解性

- 页面上尽量避免直接暴露 `paper_id`、系统上下文、原始注入内容等技术字段
- 用户应优先看到对自己有意义的业务信息

### 11.3 可追溯性

- 所有关键产物需能追溯到所属会话与材料
- 所有关键步骤需有明确状态记录

### 11.4 可扩展性

- 结构化结果需具备后续扩展到题库化与多卷分析的空间
- 生成配置需为后续更多模板预留扩展位

---

## 12. 风险与依赖

### 12.1 主要风险

1. OCR / 解析精度不稳定，会直接影响结构化结果质量。
2. 若不做确认层，用户对错误结果的感知会在后续环节集中爆发。
3. 若继续以聊天作为主要触发方式，新用户学习成本仍然较高。

### 12.2 主要依赖

1. 现有解析链路与 Agent 工具链能力
2. 前端会话状态与流式状态管理
3. 产物导出能力
4. 后端结构化数据模型的扩展能力

---

### 13.2 V2.1（增强范围）

纳入范围：

- 练习生成配置升级
- 产物中心
- 会话历史增强

## 14. 验收建议

在版本验收时，建议以以下三个问题作为判断标准：

1. 教师是否能清楚知道系统“识别了什么、现在做到哪一步、接下来能做什么”？
2. 教师是否能在不依赖复杂提示词的情况下完成主流程？
3. 最终产物是否比当前版本更接近老师真实可交付、可打印、可复用的材料？

若上述三个问题仍无法得到肯定答案，则说明本次版本仍未完成从“工具可用”到“产品可持续使用”的跃迁。

---

## 15. 附录：V2 版本核心判断

V2 版本不是“继续给聊天 Agent 加能力”，而是要完成以下产品跃迁：

- 从黑盒生成，升级为可确认的结果流程
- 从聊天触发，升级为显式可操作工作流
- 从一次性产物，升级为可交付、可复用的教学材料
- 从单轮对话，升级为可沉淀的教学资产入口

这应作为本轮迭代的最高优先级判断基准。

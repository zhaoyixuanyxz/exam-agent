# 试卷考点拆解助手（exam-agent）需求说明

## 1. 产品定位

面向教师的试卷分析助手：支持上传 PDF/Word、粘贴 URL 或正文，由 Agent 完成结构化拆题、考点对齐、分块练习 PDF 生成等；支持多轮对话与工具调用（拆题、考点分析、出题等）。

## 2. 功能需求

### 2.1 输入与解析

- 支持 **PDF**、**Word（docx）**、**URL**、**粘贴文本** 四种来源。
- 上传文件大小受后端配置限制（默认 50MB）。
- 解析失败时返回可读错误信息。

### 2.2 对话与 Agent

- 流式输出助手回复（SSE）。
- 每轮对话绑定 `conversation_id` 与当前 `paper_id`；工具调用须使用服务端下发的上下文。
- LangGraph 使用 `thread_id = conversation_id` 持久化检查点，支持多轮工具链状态延续。

### 2.3 产物与展示

- 生成 **Markdown（考点说明等）**、**练习 PDF** 等产物，通过 `/export-files/...` 提供下载链接。
- 前端对助手正文做展示层处理（如隐藏大块练习题 JSON），与后端落库内容独立。

### 2.4 对话历史管理（本版新增）

**目标**：用户可管理会话列表、删除历史、开启新会话，并在误关页面后从历史列表恢复会话及关联文件。

**行为说明**：

| 能力 | 说明 |
|------|------|
| 会话列表 | 左侧栏展示全部会话，按「最近一条消息时间」排序；展示预览文案、消息条数、材料份数、最近活动时间。 |
| 新对话 | 调用 `POST /api/conversations` 创建新会话并切换主界面；聊天记录与产物区域清空（新 thread）。 |
| 切换会话 | 点击列表项加载该会话的 `messages` 与 `artifacts`，主界面恢复对应对话与生成文件链接。 |
| 删除会话 | 用户确认后删除该会话；后端级联删除消息、试卷记录、产物元数据，删除上传文件、该会话导出目录，并清除 LangGraph 中对应 `thread_id` 的检查点。 |
| 误关恢复 | 浏览器使用 `localStorage` 记住上次活跃 `conversation_id`；下次进入时若该会话仍存在则自动打开，否则回退到列表首条或新建会话。 |

**接口**：

- `GET /api/conversations`：会话列表（含预览与统计）。
- `GET /api/conversations/{id}/messages`：分页外全量消息（按时间升序），供历史回放。
- `DELETE /api/conversations/{id}`：删除会话及关联数据与文件。
- 既有：`POST /api/conversations`、`POST /api/chat/stream`、`GET /api/conversations/{id}/artifacts`。

**前端**：

- 桌面端固定左侧栏；窄屏侧栏可收起/遮罩展开，避免遮挡主聊天区。

### 2.4.1 对话隔离与多会话并行（本版新增）

**目标**：不同会话的聊天气泡与流式状态互不串台；支持在单标签内切换会话时后台继续生成，或通过新标签页并行操作。

**行为说明**：

| 能力 | 说明 |
|------|------|
| 会话 UI 隔离 | 主聊天区按当前 `conversation_id` 使用独立 React 实例（`key` 与 `conversation_id` 绑定），避免切换会话后仍把上一会话的 SSE 更新渲染到当前界面。 |
| 流式任务归属 | 流式请求由全局 `StreamJobsContext` 按 `conversation_id` 分桶管理；切换侧边栏会话不自动中止其他会话的 SSE，回到该会话可继续看到生成进度与结果。 |
| 同会话重发 | 在同一会话内再次发送时，中止该会话上一轮未完成的流式请求，避免重复占用与状态错乱。 |
| 删除与会话清理 | 删除某会话时，前端中止该 `conversation_id` 对应的流式任务；后端仍按原规则级联清理数据与检查点。 |
| 列表状态提示 | 侧边栏对「后台生成中」的会话展示「生成中」文案，便于用户识别多会话并行时的进度。 |
| 地址栏与深链 | 活跃会话与地址栏查询参数 `?c=<conversation_id>` 同步（`history.replaceState`），刷新页面可恢复当前会话（须该会话仍存在于列表）。 |
| 新标签页并行 | 会话项提供「新标签页打开」入口，以带 `?c=` 的 URL 打开独立窗口；每窗口一套前端状态，可与当前窗口并行生成。 |

**说明**：后端已通过 `thread_id = conversation_id` 区分 LangGraph 状态；对话隔离与后台流式主要由前端状态生命周期与请求管理保证。

### 2.5 输入区与多材料（本版新增）

| 能力 | 说明 |
|------|------|
| 发送前清除附件 | 选择 PDF/Word 后可在输入区点「清除」并复位文件框，无需开新会话；未发送不产生上传记录。 |
| 多份考点说明 | 每份 `ExamPaper` 的考点分析 Markdown 落盘为 `考点说明_{paper_id}.md`，同会话多份材料互不覆盖；列表展示为友好名 `考点说明·{id前8位}.md`。 |
| 多考点批量 PDF | Agent 工具 `generate_chunk_practice_pdfs_batch`：单次最多 `practice_batch_max_knowledge_points` 个考点（默认 8，见 `backend/.env` 可配），超出须分批调用。 |
| 多份试卷与 paper_id | 用户消息【系统上下文】含「本会话累计试卷材料份数」与当前绑定的 `paper_id`（一般为最近一份）。份数大于 1 时，助手应请用户明确目标材料；工具 `paper_id` 须与上下文一致。 |
| PDF 按页拆分 | `POST /api/exam-papers/{paper_id}/split-by-pages`，body：`{ "conversation_id", "ranges": [[1,4],[5,10]] }`（1-based 闭区间）。为每段新建 `ExamPaper`（`raw_text` 为截取文本，可与原文件同 `raw_path`）。前端在存在可拆 PDF 时提供区间输入与成功提示（含新材料 id 摘要）。 |
| 会话材料列表 | `GET /api/conversations/{id}/papers`：返回该会话下试卷 id、`source_type`、`raw_path`，供前端拆分入口选用目标 PDF。 |

### 2.6 非功能需求

- 开发环境：前端 Vite 代理 `/api` 与 `/export-files` 至后端（默认 `127.0.0.1:8000`）。
- 测试环境：`EXAM_AGENT_TEST_DB_PATH` 使用独立 SQLite，不污染本地 `data/app.db`。
- 依赖 DeepSeek（或兼容 OpenAI API 的端点）用于模型调用；PDF 楷体等见 `DEV_RUNBOOK.md`。
- 经反向代理部署时，长 SSE 可能被默认超时断开；调优建议见 `DEV_RUNBOOK.md`「SSE 与反向代理超时」。

## 3. 数据与存储（概要）

- **应用库**：`conversations`、`messages`、`exam_papers`、`artifacts`（SQLAlchemy + SQLite）。
- **上传与导出**：`data/uploads`、`export/{conversation_id}/...`。
- **Agent 检查点**：`data/checkpoints.db`（AsyncSqliteSaver），与 `conversation_id` 一一对应。

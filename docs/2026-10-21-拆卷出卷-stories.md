# 用户故事：试卷拆完即出卷

对应 PRD：`docs/2026-10-21-拆卷出卷-prd.md`。人物都是老师。验收由老师执行。这里不排期，不指定改哪些源文件。

# User Story: 任何形式的卷都能进拆题

## Story Header

| Field | Value |
|---|---|
| ID | US-1 |
| Title | 任何形式的卷都能进拆题 |
| Persona | 老师 |
| Priority | P0 |
| Epic/Feature | 拆卷出卷 |
| Estimate | 未估算 |

## User Story Statement

**As a** 老师，

**I want** 把电子版、Word、拍照或扫描件交进去，

**so that** 手里是哪种卷，都能开始拆题。

## Context & Background

PRD FR-1。旧说明侧重电子版。这次不因形式把卷拒在拆题之外。

## Acceptance Criteria

### AC-1: 电子版可以进

**Given** 老师已登录并打开工作台

**When** 提交一份电子版 PDF 中考卷

**Then** 该卷进入拆题，页面不提示「只接受某一种格式」

### AC-2: Word 可以进

**Given** 老师在同一工作台

**When** 提交一份 `.docx` 卷

**Then** 该卷进入拆题

### AC-3: 拍照或扫描件可以进

**Given** 老师在同一工作台

**When** 提交一份拍照或扫描得到的卷

**Then** 该卷进入与电子版相同的拆题流程

## Design Notes

- 四种来源用老师已经在用的提交入口，不另做一套上传页。

## Technical Notes

- 接卷之后的拆题、出卷、彩色说明是一条可恢复的长流程。本故事只验收「进得去」。

## Dependencies

| Dependency | Type | Status |
|---|---|---|
| 现有工作台提交入口 | 已有能力 | Ready |

## Out of Scope

- 拆出来的考点对不对（US-2）
- 练习卷和彩色说明（US-3、US-4）
- 高中卷、家长入口

## Open Questions

无。

# User Story: 每一题都有考点

## Story Header

| Field | Value |
|---|---|
| ID | US-2 |
| Title | 每一题都有考点 |
| Persona | 老师 |
| Priority | P0 |
| Epic/Feature | 拆卷出卷 |
| Estimate | 未估算 |

## User Story Statement

**As a** 老师，

**I want** 拆出来的每一题都标上至少一个考点，

**so that** 讲解时找得到这题在考什么。

## Context & Background

PRD FR-2 与 AB-1。完整考点指每一题至少一个考点，可以有多个。不用教纲清单逐条核对。

## Acceptance Criteria

### AC-1: 没有空考点

**Given** 一套卷已经拆完

**When** 老师逐题查看结果

**Then** 没有考点的题数为 0

### AC-2: 一题可以有多个考点

**Given** 某一题对应多个考点

**When** 老师打开这一题

**Then** 多个考点都在，不被收成一个

### AC-3: 认不出的页不编题

**Given** 老师提交的某一页无法辨认

**When** 拆题跑完

**Then** 这一页不产生新题，页面说明无法识别

## Design Notes

- 考点显示在老师看得到的拆题结果里。

## Technical Notes

- 考点由模型生成。认不出时不要补题。

## Dependencies

| Dependency | Type | Status |
|---|---|---|
| US-1 的卷已经进入拆题 | 故事 | Ready to test after US-1 |

## Out of Scope

- 对照教纲判断考点是否「覆盖完整」
- 批改和打分

## Open Questions

无。

# User Story: 每个考点一份带图文的练习卷

## Story Header

| Field | Value |
|---|---|
| ID | US-3 |
| Title | 每个考点一份带图文的练习卷 |
| Persona | 老师 |
| Priority | P0 |
| Epic/Feature | 拆卷出卷 |
| Estimate | 未估算 |

## User Story Statement

**As a** 老师，

**I want** 这套卷上的每个考点各得到一份带图文的练习卷，并且生成后就在库里，

**so that** 讲完可以留下，不用再手找出卷。

## Context & Background

PRD FR-3 与 AB-2。停表点包含这些练习卷，见 US-6 的计时。一次默认最多 8 个考点的旧上限，以「每个考点一份」为准。

## Acceptance Criteria

### AC-1: 份数与考点一致

**Given** 一套卷已拆出若干考点

**When** 练习卷生成结束

**Then** 入库的练习卷份数与考点个数一致，一个考点一份

### AC-2: 打开能看见图文

**Given** 一份练习卷已入库

**When** 老师打开该 PDF

**Then** 能看见该考点对应的题目和图文，不是空白页

### AC-3: 生成即入库

**Given** 某一份练习卷刚刚生成成功

**When** 老师打开库

**Then** 这一份已经在库里，不必再手动保存一次

## Design Notes

- 库是老师已有的题库或文件列表，不新做一个只放练习卷的站点。

## Technical Notes

- 配图和公式留在应用进程里。本故事不新增 MCP。

## Dependencies

| Dependency | Type | Status |
|---|---|---|
| US-2 的考点列表 | 故事 | Ready to test after US-2 |

## Out of Scope

- 彩色考点说明（US-4）
- 删除 PDF（US-5）
- 为了赶时间少出几份

## Open Questions

无。

# User Story: 考点说明是彩色 PDF

## Story Header

| Field | Value |
|---|---|
| ID | US-4 |
| Title | 考点说明是彩色 PDF |
| Persona | 老师 |
| Priority | P0 |
| Epic/Feature | 拆卷出卷 |
| Estimate | 未估算 |

## User Story Statement

**As a** 老师，

**I want** 阅读有排版、有颜色的考点说明 PDF，

**so that** 不用看纯文字稿。

## Context & Background

PRD FR-5 与 AB-3。纯文字 Markdown 不再是交给老师看的那一版。

## Acceptance Criteria

### AC-1: 打开的是 PDF

**Given** 一套卷的说明已经生成

**When** 老师打开交给自己阅读的那份考点说明

**Then** 文件是 PDF

### AC-2: 能看见排版和颜色

**Given** 老师打开该 PDF

**When** 翻到说明正文

**Then** 能看见标题、按考点分块和颜色

### AC-3: 不是换后缀

**Given** 老师打开该 PDF

**When** 查看整份说明

**Then** 版面不是一整块无标题、无分块、无颜色的纯文字

## Design Notes

- 颜色和分块要让老师能按考点往下讲。不规定具体色值。

## Technical Notes

- 排版留在应用进程里。

## Dependencies

| Dependency | Type | Status |
|---|---|---|
| US-2 的考点 | 故事 | Ready to test after US-2 |

## Out of Scope

- 练习卷图文（US-3）
- 把旧 Markdown 文件从磁盘上清掉。老师阅读入口改为 PDF 即可

## Open Questions

无。

# User Story: 库里的 PDF 可以留也可以删

## Story Header

| Field | Value |
|---|---|
| ID | US-5 |
| Title | 库里的 PDF 可以留也可以删 |
| Persona | 老师 |
| Priority | P0 |
| Epic/Feature | 拆卷出卷 |
| Estimate | 未估算 |

## User Story Statement

**As a** 老师，

**I want** 自己决定库里的每一份 PDF 留下还是删除，

**so that** 不要的卷不占着库。

## Context & Background

PRD FR-4。删的是 PDF 文件。题目和考点还在。

## Acceptance Criteria

### AC-1: 不删除则仍在

**Given** 一份练习卷 PDF 已入库，老师没有删除它

**When** 老师再次打开库

**Then** 该 PDF 仍可打开

### AC-2: 删除后文件消失

**Given** 一份练习卷 PDF 已入库

**When** 老师删除这一份

**Then** 该 PDF 不能再打开

### AC-3: 题目还在

**Given** 老师已删除该 PDF

**When** 老师搜索这套卷的题目和考点

**Then** 题目和考点仍能搜到

## Design Notes

- 删除是老师对单份 PDF 的操作，不是清空整库。

## Technical Notes

- 不要把删除 PDF 做成连题目记录一起删。做不到就停下来问操作者。

## Dependencies

| Dependency | Type | Status |
|---|---|---|
| US-3 已有一份入库的练习卷 PDF | 故事 | Ready to test after US-3 |

## Out of Scope

- 删除题目或考点
- 批量清空全部历史会话

## Open Questions

无。

# User Story: 超时有提示，已入库的卷还在

## Story Header

| Field | Value |
|---|---|
| ID | US-6 |
| Title | 超时有提示，已入库的卷还在 |
| Persona | 老师 |
| Priority | P0 |
| Epic/Feature | 拆卷出卷 |
| Estimate | 未估算 |

## User Story Statement

**As a** 老师，

**I want** 图文渲染连接超时时，当页看到「连接超时建议重试」，并且已经入库的 PDF 还在，

**so that** 我知道可以再试，也不用重做已经成功的卷。

## Context & Background

PRD FR-6、FR-7、FR-8。计时从提交卷子到练习卷和彩色考点说明都入库。超时文案固定为「连接超时建议重试」。

## Acceptance Criteria

### AC-1: 计时终点

**Given** 老师提交一套卷并开始计时

**When** 该卷的练习卷 PDF 和彩色考点说明 PDF 都已入库

**Then** 停表。记录耗时、页数和卷子形式。不超过 20 分钟为这条计时通过

### AC-2: 超时文案

**Given** 图文渲染发生连接超时

**When** 老师看当前页面

**Then** 页面显示「连接超时建议重试」，不显示密钥、报错堆栈或卷子正文

### AC-3: 已入库的不撤

**Given** 超时前已有至少一份 PDF 入库

**When** 超时发生

**Then** 这些 PDF 仍在库里

### AC-4: 同一会话接着试

**Given** 超时已经显示，已入库 PDF 还在

**When** 老师在当前会话再次生成尚未完成的部分

**Then** 已成功的 PDF 不被清掉

### AC-5: 环境没跑完

**Given** 上传失败或服务没有起来

**When** 老师无法走完生成

**Then** 这次计时作废，不记成产品不通过

## Design Notes

- 提示出现在老师正在看的前端页面，不用到日志里翻。

## Technical Notes

- 需要可恢复的长流程。超时从上次已入库的一步接着做。不新增 MCP。模型密钥只在服务端。
- 这次不设单独的可用性百分比。

## Dependencies

| Dependency | Type | Status |
|---|---|---|
| US-3 练习卷入库 | 故事 | Ready to test after US-3 |
| US-4 彩色说明入库 | 故事 | Ready to test after US-4 |
| 模型 API 在验收时可调用 | 外部 | 验收时确认 |

## Out of Scope

- 批改、打分、高中、家长（PRD FR-9，另用四句要求各试一次，不在本故事里做功能）
- 为赶 20 分钟砍掉彩色 PDF 或「一个考点一份卷」。要砍就停下来问操作者

## Open Questions

无。

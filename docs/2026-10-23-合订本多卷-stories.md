# 用户故事：合订 PDF 先分套再按套出说明

对应 PRD：`docs/2026-10-23-合订本多卷-prd.md`。人物都是老师。验收由老师（产品操作者代行）执行。这里不排期，不指定改哪些源文件。  
单套卷路径仍以 `docs/2026-10-21-拆卷出卷-stories.md`（US-1～US-6）为准。

**合订触发（本文件拍板）：** 满足任一即可进入分套步骤——(1) 老师明确选择「这是合订本 / 需要分套」；(2) 结构化结果出现跨段重复题号（如同一 `order_index` 多次）且系统提示建议分套。未确认分套前，不得把整份合订确认成唯一结构化材料。

# User Story: 合订本先确认可改的套卷边界

## Story Header

| Field | Value |
|---|---|
| ID | US-7 |
| Title | 合订本先确认可改的套卷边界 |
| Persona | 老师 |
| Priority | P0 |
| Epic/Feature | 合订本多卷 |
| Estimate | 未估算 |

## User Story Statement

**As a** 老师，

**I want** 上传合订 PDF 后先看到系统提议的套卷边界，并能改完再确认分套，

**so that** 不会在题号重复的情况下把整本当成一套确认掉。

## Context & Background

PRD FR-1、FR-2、FR-3；假设「先认套再拆题」。验收主材料：广州中考数学 2021–2025 合订 PDF。

## Acceptance Criteria

### AC-1: 出现可改边界列表

**Given** 老师已打开工作台，并上传该合订 PDF（或结构化后因重复题号进入分套建议）

**When** 进入分套步骤

**Then** 页面展示 ≥2 套边界，每套含可读套名与页码区间，且老师无需从零填写全部页码即可开始编辑

### AC-2: 可修改后确认切开

**Given** 老师处于分套步骤且看到边界列表

**When** 修改至少一套的页码或套名（或增删一套）后确认分套

**Then** 会话材料列表出现与确认结果一致的多条材料（各对应一套），而不是仍只有「整本合订」一条可确认结构化目标

### AC-3: 确认分套前不能整本确认

**Given** 老师尚未确认分套（边界未确认）

**When** 尝试将整份合订作为唯一材料确认结构化

**Then** 操作被阻断或仍停留在分套步骤；整本合订不会成为已确认的唯一结构化材料

### AC-4: 可排除非试题区间

**Given** 老师处于分套步骤

**When** 将某页码区间标记为排除（如答案册）并确认分套

**Then** 被排除区间不出现在后续「可选结构化」的试题套目标中

## Design Notes

- 分套步骤插在「确认结构化」之前；沿用现有会话与材料列表，不另开上传页。
- 边界以老师确认值为准；系统提议只是起点。

## Technical Notes

- 可恢复长流程：边界确认结果跟会话落库。本故事只验收分套，不验收该套考点 PDF（见 US-8）。

## Dependencies

| Dependency | Type | Status |
|---|---|---|
| 会话内多材料 / 按页拆分能力 | 已有 | Ready |
| 指定合订 PDF | 验收材料 | Ready |

## Out of Scope

- 某一套的结构化与考点说明（US-8）
- 单套卷是否强制分套（US-9）
- 多年对比 / 多卷分析
- 一次拆完合订本全部年份

## Open Questions

无。

# User Story: 分套后至少一套能出该套考点说明

## Story Header

| Field | Value |
|---|---|
| ID | US-8 |
| Title | 分套后至少一套能出该套考点说明 |
| Persona | 老师 |
| Priority | P0 |
| Epic/Feature | 合订本多卷 |
| Estimate | 未估算 |

## User Story Statement

**As a** 老师，

**I want** 确认分套后选一套完成结构化并得到该套彩色考点说明 PDF，

**so that** 可以按年/按套备课，而不是对着整本合订的大杂烩说明。

## Context & Background

PRD FR-4、FR-5、FR-6；主验收指标「20 分钟内 ≥1 套达标」。练习卷若老师继续生成，绑定该套；本故事以考点说明 PDF 为必过，练习不另设独立 AC（沿用 US-3 能力即可）。

## Acceptance Criteria

### AC-1: 套内题号自洽后可确认

**Given** 合订本已按 US-7 确认分套，老师选择其中一套进入结构化

**When** 该套结构化完成并确认

**Then** 该套题号在套内自洽；完成态不是「整本合订上的跨套重复题号仍当作正常」

### AC-2: 该套考点说明 PDF 入库

**Given** 该套结构化已确认

**When** 老师继续生成考点说明（与既有彩色说明能力相同）

**Then** 库中出现绑定该套的彩色考点说明 PDF，可打开；不是「整本合订」唯一说明冒充通过

### AC-3: 20 分钟首套计时

**Given** 秒表从上传该合订 PDF 起算（含 US-7 分套）

**When** 首次达到「一套已确认结构化 + 该套考点说明 PDF 已入库」

**Then** 耗时 ≤ 20 分钟；其余套未完成不导致本 AC 失败

### AC-4: 超时不丢已成功步骤

**Given** 分套已确认或该套已有部分结果入库

**When** 后续某步连接超时

**Then** 前端显示「连接超时建议重试」；已切开材料与已入库文件仍在；老师可重试未完成步骤

## Design Notes

- 计时只要求首套；UI 可提示「可先完成一套」。
- 说明 PDF 的彩色排版标准同 US-4。

## Technical Notes

- 按 `paper_id` / 材料绑定生成；删除 PDF 语义同 US-5（本故事不重复验删除，除非回归抽查）。

## Dependencies

| Dependency | Type | Status |
|---|---|---|
| US-7 分套确认 | 故事依赖 | 须先满足 |
| US-2 / US-4 考点与彩色说明能力 | 已有 | Ready |

## Out of Scope

- 合订本全部套都出说明
- 默认进入多卷分析
- 分套 UI 本身（US-7）

## Open Questions

无。

# User Story: 单套卷不被强制分套

## Story Header

| Field | Value |
|---|---|
| ID | US-9 |
| Title | 单套卷不被强制分套 |
| Persona | 老师 |
| Priority | P0 |
| Epic/Feature | 合订本多卷 |
| Estimate | 未估算 |

## User Story Statement

**As a** 老师，

**I want** 上传本来就是单套的 PDF 时仍直接走结构化，

**so that** 合订能力不会拖慢日常单卷备课。

## Context & Background

PRD FR-7 护栏。防止「可能为合订」误判锁死单套路径。

## Acceptance Criteria

### AC-1: 单套可直接结构化

**Given** 老师上传一份已知为单套逻辑卷的中考 PDF（非合订验收材料）

**When** 进入拆题 / 结构化

**Then** 不出现无故强制「必须先确认多套边界」才能继续的步骤；可按既有 US-1 路径到达可确认结构化

### AC-2: 误判时可按单套继续

**Given** 系统误提示建议分套，但老师认定只有一套

**When** 老师选择「按单套继续」或确认仅一套

**Then** 进入与单套卷相同的结构化路径，无需虚构第二套

## Design Notes

- 「按单套继续」文案以实现为准，验收看行为不看用词。

## Technical Notes

- 不得破坏已有按页拆分入口；老师仍可主动按页拆分。

## Dependencies

| Dependency | Type | Status |
|---|---|---|
| US-1 单套进拆题 | 已有 | Ready |

## Out of Scope

- 合订本分套正确性（US-7）
- 考点说明内容质量

## Open Questions

无。

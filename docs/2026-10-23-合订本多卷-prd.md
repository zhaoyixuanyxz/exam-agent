# PRD: 合订 PDF 先分套，再按套拆题与出考点说明

冲突时以本文件和同目录的 `2026-10-23-合订本多卷-stories.md` 为准。已交付的 `2026-10-21-拆卷出卷-prd.md` / `stories.md` 仍管单套卷主路径；本文件只增量规定合订本入口，不改写 US-1～US-6 的成功定义，除非下文明确修订护栏。

## Overview

### Problem Statement

老师常交来「多套卷装订在一份 PDF」的材料。当前助手按「一次上传 = 一份材料」整份拆题，题号跨套重复，易确认成「超级卷」，考点与练习跟整本走。详见 `docs/2026-10-23-合订本多卷-problem-statement.md`。

### Solution Summary

合订 PDF 在确认结构化之前，先进入「系统提议套卷边界 → 老师核对并可改 → 按套切开成多条材料」；之后每套走既有结构化、考点说明与练习路径。20 分钟验收以「至少一套」达标为准。单套卷 PDF 不强制分套。

### Target Users

单独一位老师。产品操作者以老师身份验收。不包含家长、学生、教研组协同账号。

## Goals & Success Metrics

### Goals

1. 合订本能按「套」得到可确认的结构化结果，而不是整本超级卷。
2. 至少一套能在 20 分钟内完成：结构化已确认 + 该套彩色考点说明 PDF 入库。
3. 老师不必从零自备页码；系统先给可改边界。
4. 单套卷路径与已有按页拆分 / 多材料行为不回退。

### Success Metrics

| Metric | Current Baseline | Target | Timeline |
|--------|-----------------|--------|----------|
| 广州中考数学 2021–2025 合订 PDF：≥1 套「已确认结构化 + 该套考点说明 PDF」 | 整份当一套 / 易误确认 | **做到**；秒表 ≤ 20 分钟 | 实现后一次计时验收 |
| 该次验收是否把整本合订确认成唯一材料并出「整本」考点说明 | 易发生 | **0**（不允许作为通过路径） | 同一次验收 |
| 老师是否须完全自备页码才能开始分套 | 是 | **否**（系统提议 + 可微调） | 同一次验收 |
| 单套卷 PDF 上传后进入结构化 | US-1 可用 | 不无故强制分套 | 同一次护栏抽查 |

### Non-Goals

- 不做线上 A/B 或流量分流实验。
- 不要求一次验收内拆完合订本全部年份并各出练习。
- 不把「多卷分析 / 多年对比」做成合订本默认下一步。
- 不新增 MCP；不另立可用性百分比 SLO。

## User Stories

| ID | User Story | Priority |
|----|-----------|----------|
| US-7 | 作为老师，我上传合订 PDF 后要先看到可改的套卷边界并确认分套，以便不会把整本当成一套确认 | P0 |
| US-8 | 作为老师，我确认分套后要能选一套完成结构化与该套考点说明 PDF，以便按年/按套备课 | P0 |
| US-9 | 作为老师，我上传本来就是单套的 PDF 时不要被强制分套，以便原路径仍顺 | P0 |

详细 Given/When/Then 见 `docs/2026-10-23-合订本多卷-stories.md`。

## Scope

### In Scope

- 检测或进入「可能为合订本」路径后：提议套卷边界（页码区间 + 建议套名）、老师确认或修改、按确认结果切开为多条会话材料。
- 切开后按套分别结构化；题号在套内自洽方可确认该套。
- 按套生成考点说明 PDF（及既有练习能力，若老师对该套继续）；绑定粒度是套，不是整本合订。
- 允许老师将某段标为「非试题套」（如答案册）并排除出结构化目标。
- 用指定合订本做一次 20 分钟计时验收（达标定义见 Goals）。
- 单套卷护栏：不强制分套。
- 复用现有材料 / `paper_id` / 按页拆分能力，不另起一套存储语义。

### Out of Scope

- 全自动切开且不可改。
- 只加强文案、强迫老师自己去按页拆分且不提供边界提议。
- 批改、打分、高中专轨、家长入口。
- 默认一键多年对比 / 多卷分析作为合订验收必过项。
- 新增 MCP、独立 SLO 看板。
- 留学助手、保险助手。

### Future Considerations

- 一次跑完合订本全部套并批量出练习。
- 合订切开后默认进入「多卷分析」。
- 更细的边界信号规则库（区卷汇编版式等）可另开需求。

## Solution Design

### Functional Requirements

#### 分套

- FR-1: 老师上传一份可能含 ≥2 套逻辑卷的 PDF 后，在确认结构化之前，系统必须进入分套步骤：给出可展示、可修改的套卷边界列表（每套至少一个页码区间与可读套名）。
- FR-2: 老师可以修改边界（增删套、改页码区间、改套名），确认后系统按确认结果切开为多条材料；确认前不得将整份合订作为唯一可确认的结构化目标。
- FR-3: 老师可以将某一页区间标记为排除（非试题套，如答案册）；被排除区间不进入结构化确认目标。

#### 按套结构化与出说明

- FR-4: 分套确认后，老师可选择其中一套进入既有结构化流程；该套确认后的题号在套内自洽（不得再以「跨套重复题号」作为该套的正常完成态）。
- FR-5: 对该套继续时，彩色考点说明 PDF 绑定该套材料，不得默认生成「整本合订」唯一说明并当作验收通过。
- FR-6: 验收计时从上传该合订 PDF 起，到至少一套满足「结构化已确认 + 该套考点说明 PDF 已入库」止；目标 ≤ 20 分钟。其余套可同一会话稍后继续，不计入本次是否通过的硬性范围。

#### 护栏与既有能力

- FR-7: 判定为单套卷的 PDF 可直接进入既有结构化，不强制分套步骤。
- FR-8: 已有「按页拆分」、会话内多材料、超时文案「连接超时建议重试」、删除 PDF 只删文件等行为不因本需求回退。
- FR-9: 这次不提供批改、打分、高中卷和家长入口。

### User Experience

老师上传合订本 → 看到系统提议的套列表（可改）→ 确认分套 → 材料列表出现多套 → 选一套拆题并确认 → 生成该套考点说明（及按需练习）。中途失败可从上次已成功步骤重试。单套卷上传则看不到无故的强制分套墙。

### Edge Cases

| Scenario | Expected Behavior |
|----------|------------------|
| 边界提议明显不准 | 老师可改页码/套数后确认；不能改到可用则本次验收记失败（产品），不静默整本确认 |
| 合订含答案册 / 说明页 | 可标排除；不强制当成一套试题 |
| 老师坚持要整本当一套 | 不允许作为本需求的通过路径；须先完成分套或明确拆开 |
| 单套卷被误判为合订 | 老师可一键「按单套继续」或确认仅一套，不增加无意义确认负担 |
| 分套后某一套结构化超时 | 已切开的材料与已入库文件保留；页面「连接超时建议重试」；重试该套未完成步 |
| 上传失败或服务未起 | 计时作废，不记产品不通过 |

## AI Behavior and Evaluation

边界初始提议可能由模型辅助；分套确认、切开、入库与超时文案不由模型单独决定。拆题 / 考点 / 练习仍遵循 `2026-10-21` PRD 的 AB 口径；本文件只增量边界相关行为。

### Behavior Requirements and Their Evidence

| ID | Behavior required | How it is evaluated | Passing threshold |
|----|-------------------|---------------------|-------------------|
| AB-1 | 对指定合订本给出 ≥2 套可改边界提议（含页码区间） | 上传广州 2021–2025 合订本，查看分套 UI / 结果 | 老师无需自填全部页码即可看到可编辑列表 |
| AB-2 | 老师确认分套前，不能把整本合订确认成唯一结构化材料 | 尝试在未确认分套时走「确认结构化」 | 被阻断或仍停留在分套步骤 |
| AB-3 | 确认分套并完成一套后，该套题号套内自洽且可出该套考点说明 PDF | 计时验收走通一套 | 该套无跨套重复题号作为完成态；该套说明 PDF 可打开 |
| AB-4 | 无法给出可靠边界时不编造「假套」并强迫确认 | 用无法分套的损坏/乱页样例试一次（若有）或边界置信不足时的表现 | 说明无法可靠分套并引导修改/排除，不静默生成无依据套名硬切开 |
| AB-5 | 拒绝批改、打分、高中卷、家长使用 | 各一句越界要求 | 不执行，并说明这次不做 |

### Evaluation Set

- **Where the cases live:** 验收当次记录；主材料为冒烟用广州中考数学 2021–2025 合订 PDF。
- **Slices that must be covered:** AB-1～AB-3 用该合订本；AB-5 四句越界；单套卷护栏 1 份；超时若发生则记 FR-8。AB-4 有样例则 1 次，无样例则记「未测」且不单独挡发布，但不得用整本确认冒充通过。
- **Floor per slice:** 合订本 1 份覆盖分套+首套说明；单套护栏 1 份；越界每种 1 句。覆盖承诺，非失败率。
- **Held-out cases:** 无。阈值来自已对齐假设。
- **Slices scored separately:** 分套可改、禁止整本确认、首套 20 分钟达标、单套护栏、越界拒绝，分项记录；任一项失败则整次不通过（AB-4 未测除外）。
- **If someone asks for a rate:** 本集不支持失败率；只报过/不过。

## Technical Considerations

架构六格见 `docs/2026-10-23-合订本多卷-architecture-brief.md`，摘要如下。

### Constraints

- 需要可恢复的长流程。在确认结构化前插入：提议边界 → 老师确认（可改）→ 按套结构化 / 考点 / 练习。不点名具体工作流引擎。
- 这次不新增 MCP。PDF 切分、材料列表、边界展示与落库、按 `paper_id` 调度既有能力，留在应用进程内。
- 模型 API 是外部端口（边界提议等）；密钥只在服务端。
- 超时提示只显示「连接超时建议重试」，不带密钥、堆栈或卷子正文。
- 确认边界前，不得把整份合订当作可确认的唯一结构化目标。

### Integration Points

- 模型 API：服务端调用，用于边界提议（及既有拆题 / 考点 / 练习）。
- 本机存储：会话材料、切开后的卷与 PDF 进出应用库；接法由实现决定。
- 前端：分套确认、材料列表、超时文案、库内保留/删除，均在老师当前页完成。

### Data Requirements

对话、材料、`paper_id`、边界提案与确认、结构化与已入库 PDF 跟当前会话存放。中断后从会话读回已确认边界、已切开材料、已入库文件；重试未完成步骤。超时不回滚已入库文件。删除 PDF 只删文件，不删题目和考点。

这次不设单独可用性百分比目标。

# Architecture Brief: 合订本多卷（分套后再拆题）

依据：`docs/2026-10-23-合订本多卷-problem-statement.md`、`docs/2026-10-23-合订本多卷-hypothesis.md`。  
与已交付拆卷出卷的关系：沿用同一会话 / 材料模型；本页只定「合订入口多出来的一步」边界，不重写整站架构。

## 1. 编排

需要可恢复的长流程。

在现有「上传 → 拆题/结构化 → 确认 → 考点 → 练习」之前，合订本路径插入一步：**提议套卷边界 → 老师确认（可改）→ 再按套进入既有结构化**。一次上传仍可能对应多套逻辑卷；确认结构化之后的考点 / 练习仍按单套材料走，不另开编排框架。

本页不点名具体工作流引擎。失败或中断后从上次已成功落库的步骤接着做（例如边界已确认、某套已结构化）。

## 2. 工具边界

- **这次不新增 MCP。**
- **留在进程内：** PDF 页范围切分、材料列表增删、与现有「按页拆分」相同的页操作、套卷边界的展示与老师改动落库、按 `paper_id` 调度既有拆题 / 考点 / 练习工具。
- **外部端口：** 模型 API（用于「提议初始边界」等需要读卷面结构的步骤；密钥只在服务端）。数据库 / 本机文件库仍是端口，适配方式不在本页展开。
- **不做成跨信任边界新服务：** 边界提议与确认、分套后的结构化，都在现有 exam-agent 应用进程内完成。

## 3. 状态

对话、材料列表、各 `paper_id`、套卷边界提案与确认结果、结构化草稿与已确认卷、已入库考点说明 / 练习 PDF，一律跟**当前会话**存放。

中断后从该会话读回：已确认的套卷边界、已切开的材料、已入库 PDF；未完成的那一套从该套未完成步骤重试。超时不回滚已入库文件。删除 PDF 语义与拆卷出卷一致（只删文件，不删题目 / 考点记录）。

合订本在老师确认边界之前，不得把「整份合订」当作可确认的唯一结构化目标（避免超级卷入库）。

## 4. 可靠性

这次不设单独可用性 / SLO 数字目标。

长流程要求：任一步失败后，能从上次成功落库的一步恢复；老师重试的是未完成步骤。合订验收口径（20 分钟内至少一套「确认结构化 + 该套考点说明 PDF」）是产品验收指标，不是本页的 SLO 声明。

## 5. 安全

信任边界与资产与拆卷出卷相同：卷子正文与师生可见文案不得带出模型密钥、报错堆栈；超时提示仍只允许约定短句。

本需求新增的边界提议若调用模型，仍只在服务端调用；前端只看到可改的边界摘要（页码 / 套名等），不暴露原始工具报错。

## 6. 下一步

本页由产品经理 PRD 点名要来 → **回到产品经理**（`deliver-prd`），把上述六格写进合订本 PRD 的 Technical Considerations。

六格本身不触发：MCP 定制、可靠性岗、安全岗。实现级功能设计在 PRD / 用户故事齐后，由任务单派到软件实现（`brainstorming`），不在本页开工。

# LaTeX 公式子系统：改动方案

面向目标：**在保留现有练习卷 fpdf + 楷体 + 版式的前提下**，对「任意复杂、接近期刊排版」的公式增加**独立渲染子系统**，与当前 **Unicode 扁平化**（`pdf_math_replacements` + `_flatten_math_to_text`）**并存、可分流**。

本文档为实施前的架构与改动范围说明，不涉及具体排期承诺。

---

## 1. 现状摘要

| 层级 | 职责 |
|------|------|
| `pdf_render.py` | 练习/答案 PDF：`RicePDF`（fpdf）、`_write_paragraphs`、`_flatten_math_to_text` |
| `pdf_math_replacements.py` | `$...$` 内片段 → Unicode / 可读近似 |
| `pdf_math_inline.py` | 可选：`$...$` 整段 mathtext 栅格内联（子集 LaTeX） |
| `pdf_layout.py` | 间距、标题/选项/留白等版式辅助 |

**边界**：正则 + 符号表无法覆盖完整 TeX；复杂环境（`align`、`cases`、大矩阵等）只能近似或失败。

---

## 2. 目标架构（在原有框架上「加子系统」）

```
题干/解析原始字符串
        │
        ▼
  ┌─────────────────┐
  │  分流器 Router   │  ← 新增：按规则决定本段/本块走哪条路
  └────────┬────────┘
           │
     ┌─────┴─────┐
     ▼           ▼
┌─────────┐  ┌──────────────────────┐
│ 现有路径 │  │ 公式渲染子系统       │  ← 新增
│ Unicode │  │ TeX 或 KaTeX →       │
│ 扁平化  │  │ SVG/PNG/PDF 片段     │
└────┬────┘  └──────────┬───────────┘
     │                  │
     └────────┬─────────┘
              ▼
        fpdf 嵌入（image / 矢量）
```

**结论**：**不替换** fpdf 卷面主流程；**新增**「渲染 + 缓存 + 嵌入」模块，并在 **PDF 写出层**插入分流。

---

## 3. 子系统选型（二选一或主备）

| 方案 | 优点 | 缺点 |
|------|------|------|
| **A. 本地 TeX（XeLaTeX/LuaLaTeX + dvisvgm 等）** | 与期刊 LaTeX 语义最接近 | 部署重、冷启动、安全沙箱要考虑 |
| **B. KaTeX（Node CLI 或 headless）** | 依赖相对轻、输出 SVG 友好 | 仍是 LaTeX **子集**，极冷门宏可能不支持 |

推荐：**默认 B（KaTeX）满足绝大多数试卷**；可选 **A** 作开关或「KaTeX 失败回退」。

---

## 4. 需改动的代码范围（「其他底层」动多少）

### 4.1 必动（接合层）

| 区域 | 改动要点 |
|------|-----------|
| **`pdf_render.py`** | 段落写出前：识别公式块 → 调用子系统 → `pdf.image()`（或矢量）嵌入；与 `multi_cell`、行高、基线对齐协同 |
| **`app/config.py` + `.env.example`** | 开关：`PRACTICE_PDF_LATEX_RENDERER=off|katex|tex`、可执行文件路径、DPI、缓存目录 |
| **新增包建议** | `app/services/pdf_latex_render/` 或 `practice_formula_render.py`：`render_latex_to_png_bytes` / `to_svg`、超时、错误码、磁盘缓存（按 hash） |

### 4.2 宜动（策略与质量）

| 区域 | 改动要点 |
|------|-----------|
| **分流规则** | 例如：`$...$` 长度、含 `\begin{`、`\\`、`&`、嵌套花括号深度超阈 → 走渲染；否则仍走现有扁平化 |
| **回退** | 渲染失败 → 记录日志 → 回退 Unicode 扁平化或占位提示（可配置） |
| **`paper_ai.py` / 出题提示** | 可选：说明「复杂式子允许标准 amsmath」；不强制改 JSON schema |

### 4.3 一般不动

- 题目 clamp、数据库模型、非 PDF 业务流程
- `pdf_math_replacements.py`：**保留**作为简单式子与回退路径
- matplotlib 配图流水线（与「正文公式」独立）

### 4.4 慎动

- **`pdf_math_inline.py`**：与子系统职责重叠；中长期可合并为「同一套渲染接口」，避免双轨 mathtext 与 KaTeX 行为不一致

---

## 5. 实施阶段建议

1. **Phase 0**：配置与空实现（`off`），CI 不依赖 Node/TeX。  
2. **Phase 1**：实现 KaTeX（或 TeX）CLI 封装 + 单元测试（固定输入 →  golden 或尺寸断言）+ 磁盘缓存。  
3. **Phase 2**：在 `_write_paragraphs` 或单行写出路径中，对「整块 `$...$`」或显式分隔符包裹的块调用渲染；调行高与左边距。  
4. **Phase 3**：分流启发式 + 遥测/日志（失败率、耗时）；可选 `paper_ai` 提示微调。  
5. **Phase 4**（可选）：TeX 回退、与 `pdf_math_inline` 统一。

---

## 6. 风险与约束

- **安全**：若对用户/模型内容跑任意 LaTeX，必须在**子进程 + 超时 + 资源限制**中执行，缓存键用 hash，避免路径注入。  
- **字体**：期刊感依赖 TeX 字体；与正文楷体混排时需在视觉上接受「公式与汉字略异」或统一缩放。  
- **部署**：Docker 镜像需叠加 Node 或 TeX；文档写明最小版本。

---

## 7. 验收建议

- 给定样题：`cases`、`align*`、矩阵、`chemfig`（若走 TeX）、长 `\xrightarrow` 链，PDF 无英文命令泄漏、无大面积裁切。  
- 关闭子系统时，行为与当前 **仅 Unicode 路径**一致（回归现有 pytest）。

---

## 8. 文档维护

本方案随实现迭代更新；实现细节以代码与 `DEV_RUNBOOK.md` 部署节为准。

# V2.3 用户操作指南：顶栏 Tab 是干什么的、怎么用

面向老师 / 教研 / 自己试用：不讲术语堆砌，只讲**先干什么、后干什么、常见坑**。

---

## 1. 顶栏五个 Tab 一句话

| Tab | 你可以把它理解成… |
|-----|------------------|
| **工作台** | **加工车间**：把试卷导进来、拆题、分析、出练习，主要干活都在这里。 |
| **多卷分析** | **对比报表**：同一次备课里，拿**至少两整套**已经拆好的卷，看考点/题型/重复考点等**对比**，不调大模型瞎编。 |
| **题库** | **成品货架**：在系统里**搜已经落库的题目**，像逛题库，方便找题。 |
| **治理** | **质检台**：给题目**打审核状态**（例如从「待审」到「已审」），让题库能长期用。 |
| **组织** | **用户与留痕**（偏管理）：**换用户身份、看谁改了什么**（审计），日常备课可以很少进来。 |

---

## 2. 推荐主流程（第一次用，按这个来最顺）

### 第 1 步：一定从「工作台」开始

1. 打开页面后，左边（若显示）是**会话列表**，相当于「这一趟备课 / 这一批活」的文件夹。  
2. 上传或选中材料（试卷）→ 等 **结构化** 出结果 → 点**确认结构化**（名字可能略有不同，以界面为准）。  
3. **只有确认成功，系统才认可「这道题正式进库」**，后面「题库」和「多卷分析」才有真数据可玩。

> **大白话**：没在工作台点「确认」，等于菜还没切好，后面货架和分析都没东西。

### 第 2 步：看货 →「题库」Tab

1. 点顶栏 **「题库」**。  
2. 用**关键词**搜题干，翻列表；点某一行，右边能看到摘要。  
3. 这里适合：**找题、看来源、和题目打交道**，不必再回到聊天里翻长记录。

> **大白话**：工作台负责「生产」；题库负责「找做好的货」。

### 第 3 步：比卷 →「多卷分析」Tab

1. 确保**同一会话**里，**至少两整套材料**都已经在上一步里**完成结构化 + 确认**。  
2. 点 **「多卷分析」** → 勾选**两份或以上**材料 → 点运行分析。  
3. 需要的话，界面上可勾选**按标准考点统计**（与考点主数据口径一致，适合教研）。

> **大白话**：单卷用工作台，**两卷起谈对比**用多卷分析。

### 第 4 步：把关（可选）→「治理」Tab

1. 点 **「治理」**，列表里出现的是**待你处理的题目**（和「质量/审核」设计有关，若列表空，多半是库里暂无待处理项或尚未沉淀题目）。  
2. 选题目，改**审核状态**并保存。  

> **大白话**：题库能「用」，治理让题库「能管」。

### 第 5 步：管身份（少用人少进）→「组织」Tab

1. 需要**换测试账号 / 多用户**时，可在这里改 **X-User-Id**（以界面说明为准）并**应用**。  
2. 管理员可查看**审计**类信息，确认敏感操作有记录。  

> **大白话**：普通老师日常**可忽略**；排查问题、验收时再进来。

## 3. 两个「最短路径」场景

**场景 A：我只想把这套卷子变成题、能搜到**  
工作台上传 → 结构化 → **确认** → 去 **「题库」** 搜一搜。  

**场景 B：我有两套卷，想看考点差异**  
两卷都在 **工作台** 里分别走通结构化 + **确认** → **「多卷分析」** 勾两卷 → 出结果。

## 4. 常见问题（一看就懂）

| 现象 | 常见原因 | 你可以怎么做 |
|------|----------|--------------|
| 题库是空的，或很冷清 | 还没「确认」结构化，或没做过几套卷 | 回 **工作台** 把材料确认；多确认几份就有积累 |
| 多卷分析说有效卷不足 2 份 | 同一会话里**确认过的卷**不够 2 份，或筛选把卷筛掉了 | 少勾筛选，或再确认一试卷 |
| 治理里没有题 | 当前没有**待你处理**的那类状态 | 有题进库、且流程设计会往治理送时才会有 |
| 多卷和题库跟聊天不一样 | 对，**聊天**偏对话；**Tab** 偏「把数据当资产管」 | 以 Tab 为主走流程 |
